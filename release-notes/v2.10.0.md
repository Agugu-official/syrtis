## Features

- **Individual menu bar items can show when their quota resets, and the main item can be hidden.** [#519](https://github.com/Nanako0129/syrtis/pull/519) — thanks [@mijatovicmilan](https://github.com/mijatovicmilan)

  "Individual item display" in Settings → Menu bar → Individual items has three choices: Percentage only, the existing look and still the default; Percentage and reset time, on one line, such as `82% · 3h 12m`; and Compact two-line, which stacks the percentage over the reset time beside the client's icon. The reset time follows the same quota window as the percentage. It is left out when that window has no reset time or can't be read, and the compact layout shows "—" in its place.

  "Hide main menu bar item" hides Syrtis's main item while at least one individual item is showing. When every individual item is turned off or hidden, the main item comes back.

## Fixes

- **An extra Claude account stopped showing usage once its login expired.** [#513](https://github.com/Nanako0129/syrtis/pull/513) — thanks [@2011004163](https://github.com/2011004163)

  For an account added with "Add config dir…" under Claude accounts, Syrtis read the login from that folder's own Keychain item but never renewed it. Once it expired, the card said the credentials had expired until you ran `claude` with `CLAUDE_CONFIG_DIR` set to that folder. Syrtis now renews it in that folder's Keychain item, as it already did for the main account, and leaves the main account's item untouched.

- **Syrtis kept reading OpenCode's old `auth.json` after OpenCode v2 moved sign-ins into its database.** [#516](https://github.com/Nanako0129/syrtis/pull/516) — thanks [@savourylie](https://github.com/savourylie)

  OpenCode v2 copies `auth.json` into its database once and keeps sign-ins there from then on. A new OpenCode Go key, or signing out in OpenCode v2, therefore never reached Syrtis, which kept using the old file for OpenCode Go and GitHub Copilot quota and for the subscriptions it links to OpenCode usage. Syrtis now reads the database and uses `auth.json` only when there is no usable database. If the database exists but can't be read, Syrtis reports an error instead of falling back to the old file.
